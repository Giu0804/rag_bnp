# LLM-as-a-Judge: Context Attribution Evaluation (No Citation)

## Overview & Goal
This module evaluates whether the information generated by an LLM actually originates from the provided context paragraphs. Since the evaluated answers do not contain inline citations, we use an advanced **LLM-as-a-Judge ensemble approach**. 
The system queries three distinct LLMs (Judges) with advanced reasoning capabilities to independently analyze the answer and identify which context chunks were utilized. We then apply a **Majority Vote consensus** (at least 2 out of 3 judges must agree) to determine the final accepted list of Ground Truth (GT) chunks.

## Architecture
The architecture is split into an asynchronous execution engine and a post-processing consensus engine:
1. **Asynchronous API Engine**: Handles high-throughput concurrent requests (`asyncio.Semaphore`). It is highly flexible and natively supports different backend architectures: standard OpenAI-compatible endpoints (`llmas`), local vLLM servers (`vllm`), and local Qwen servers (`qwen`). It explicitly handles Qwen's specific requirements (streaming and `xhigh` reasoning effort).
2. **Consensus Engine**: LLMs output raw text (e.g., `"[1, 3]"`). A parsing function (`clean_predictions`) safely evaluates this string into actual Python lists of integers using `ast.literal_eval` and fallback regex. Finally, a `majority_vote` function aggregates the IDs and keeps only those passing the $\ge 2$ frequency threshold.

## File Structure
- `llm_judge.py`: The core asynchronous execution file. Contains the `LLMJudge` class to handle varying API specifications and the `run_judge_pipeline` function for parallel batch processing.
- `preannotation.py`: The post-processing script. Contains robust parsing logic (`clean_predictions`) to extract IDs from LLM strings, and the consensus algorithm (`majority_vote`).
- `notebook_judge_no_citation.ipynb`: The orchestrator notebook. It configures the three judges, runs them sequentially to avoid server overloads, merges their predictions via `sample_id`, and applies the final consensus vote to generate the `preannotation` column.
